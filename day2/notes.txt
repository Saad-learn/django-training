What is an App in Django?
In Django, an app is a self-contained module that performs a specific function in a project.
Key Idea:
Project = Whole website,  App = A feature of that website
Examples:
A website can have multiple apps:
accounts → login, signup, profile, blog → posts, comments
products → product listing, payments → payment processing
Each app:
Is reusable, Has its own models, views, and URLs , Handles one responsibility
Django follows modular design, which makes code clean and maintainable.


startapp Command
The startapp command is used to create a new Django app.
Syntax:
python manage.py startapp app_name
Example:
python manage.py startapp blog

Purpose of important files:
models.py → Database tables
views.py → Business logic
admin.py → Register models in Django admin
apps.py → App configuration
migrations/ → Database changes

Models (models.py)
Models define database structure using Python classes.
Example:
from django.db import models
class Post(models.Model):
    title = models.CharField(max_length=100)
    content = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)
    def __str__(self):
        return self.title

What models do:
Create database tables
Handle database queries
Use Django ORM (Object Relational Mapping)

Views (views.py)
Views handle logic and responses.
Example:
from django.http import HttpResponse
def home(request):
    return HttpResponse("Welcome to Django")
Types of views:
Function-Based Views (FBV)
Class-Based Views (CBV)
Views:
Receive HTTP request
Process data
Return HTTP response (HTML, JSON, etc.)


URLs (urls.py)
URLs map URL paths to views.
App-level urls.py (create manually):
from django.urls import path
from . import views
urlpatterns = [
    path('', views.home, name='home'),
]
Project-level urls.py:
from django.urls import path, include
urlpatterns = [
    path('blog/', include('blog.urls')),
]
Purpose:
Controls routing
Makes URLs clean and readable

Registering Apps in INSTALLED_APPS
After creating an app, Django must be told about it.
Location: settings.py
Example:
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'blog',  # custom app
]
Why this is important:
Django loads app models
Enables migrations
Registers admin features
Allows app usage in project

 important : If you forget this, Django will not recognize your app.

Django Settings Deep Dive (settings.py)
The settings.py file controls entire project configuration.


BASE_DIR:
BASE_DIR = Path(__file__).resolve().parent.parent
Root directory of the project
Used to build file paths


DEBUG
DEBUG = True
Shows detailed error pages
Must be False in production


ALLOWED_HOSTS:  ALLOWED_HOSTS = []
Domains allowed to access the project
Example:
ALLOWED_HOSTS = ['localhost', '127.0.0.1']
INSTALLED_APPS:
Registers Django and custom apps.


MIDDLEWARE:
Middleware processes requests and responses.
Example:
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
]
Middleware handles:
Security
Sessions
Authentication
CSRF protection


TEMPLATES:
Controls HTML templates
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
    },
]
DIRS → global templates
APP_DIRS → app-level templates


DATABASES:
Database configuration.
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}


Django supports:
SQLite ,PostgreSQL, MySQL ,Oracle
STATIC_URL:
Static files (CSS, JS, Images)
STATIC_URL = '/static/'


MEDIA_URL:
User-uploaded files.
MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'
